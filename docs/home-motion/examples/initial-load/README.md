# Начальная анимация · примеры iOS и Android

[Поведение и параметры](../../animations/03-initial-load.md) · [SwiftUI](InitialLoad.swift) · [Jetpack Compose](InitialLoad.kt)

Это примеры подключения анимации, а не новые компоненты дизайн-системы. Используйте свои названия, оформление карточек, скелетоны и источник данных. Код не устанавливает длительность загрузки.

## Общая схема подключения

1. Владелец главного экрана хранит состояние анимации. Возврат с дочернего экрана использует тот же экземпляр состояния.
2. Пока приложение загружает контент, передавайте признак готовности `false`. Скелетоны остаются видимыми неограниченно долго.
3. По готовности передайте `true`. Это T = 0. Повторный сигнал не запускает последовательность заново.
4. Основной контейнер показывает все скелетоны поверх контента. В него передаются существующие виды приложения.
5. Отдельный пример слота применяет высоту к кешбэку и прозрачность, масштаб и угол к приглашению. Внутри кешбэка закрепите сумму в 12 pt/dp от нижней границы. Шрифт остаётся прежним.
6. Внешняя высота области постоянна. Размеры слота в примере — из текущего макета; используйте соответствующие токены приложения.
7. Автопереключения включайте после завершения всей последовательности и только при активном главном экране.

Шиммер передаётся из вашей дизайн-системы: проход 1000 мс, пауза 1000 мс, повторение до готовности. При уменьшении движения передавайте статичные заглушки. Реализация рисования шиммера в эти примеры не входит; его полный набор параметров указан в спецификации.

## iOS

SwiftUI, iOS 17+. `InitialLoadMotion` хранится в `@StateObject` у владельца главного экрана. `InitialLoadExample` получает этот объект, `contentReady`, загруженный экран и скелетоны. `BenefitsMotionExample` показывает применение параметров к существующим видам карточек.

Системное уменьшение движения читается из окружения. Завершение каждого геометрического этапа запускает следующий; меняющиеся прозрачность и масштаб связаны одним прогрессом. При включении уменьшения движения посреди перехода устанавливается конечное состояние.

Если закрывается только дочерний экран, не создавайте состояние заново. При окончательном закрытии главного экрана отмените последовательность через `finishImmediately()` или уничтожьте её владельца. Завершение без анимации не должно запускать авто-переключения на неактивном экране — это проверяет приложение.

## Android

Jetpack Compose. `InitialLoadMotion` хранится у владельца главного экрана, например в состоянии экрана, которое живёт выше дочерней навигации. Для нового открытия создаётся новый экземпляр. `InitialLoadExample` запускает последовательность только при `contentReady=true`.

В примере параметр `reduceMotion` приходит от приложения: свяжите его с принятой в проекте политикой доступности и системными настройками анимации. Изменение параметра во время движения завершает последовательность без повторного появления скелетонов.

`animateTo` завершается перед началом следующего этапа. При отмене владельца состояние сразу становится конечным. Проверяйте `isFinished` вместе с активностью экрана перед запуском каруселей. Для действий существующих карточек используйте `enabled = !isWaiting`, чтобы блокировка охватывала также клавиатуру и средства доступности. Декоративные скелетоны не должны иметь собственных действий.

## Проверка и границы

Примеры не включают сеть, маршрутизацию, политику ошибок и оформление карточек. Временных ограничений загрузки нет. Имена типов и свойств условные.

Для подключения в продукт проверьте сборку на целевых версиях SDK, длительную загрузку, повторную готовность, возврат из дочернего экрана, отмену и уменьшение движения. Состояние анимации должно принадлежать стабильному владельцу экрана.

API и подход к последовательности сверены с официальными справочниками: [SwiftUI animations](https://developer.apple.com/documentation/swiftui/animations), [Compose: последовательные анимации](https://developer.android.com/develop/ui/compose/animation/quick-guide), [Compose Animatable](https://developer.android.com/reference/kotlin/androidx/compose/animation/core/Animatable).

Локальная проверка: SwiftUI-пример прошёл проверку типов компилятором Swift с SDK macOS 14. Целевые сборки iOS и Android и запуск на устройствах не выполнялись: их SDK отсутствуют в рабочем окружении. Примеры следует проверить в проектах приложений.
