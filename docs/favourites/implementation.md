# Реализация и перенос на другую платформу

[← Обзор](README.md) · [Поведение](behaviour.md) · [Проверка](verification.md)

## Что нужно сохранить независимо от стека

1. **Данные меняются отдельно от картинки.** Сохранение/удаление выполняется сразу. Анимация не подтверждает операцию за пользователя и не блокирует окно отмены.
2. **Карточка узнаётся по id.** Не по индексу: индекс меняется при вставке и удалении. Старый объект движется, а не заменяется копией в другом слоте.
3. **У соседей общий отсчёт времени.** У каждой карточки своя задержка, но одна начальная отметка и один прогресс движения.
4. **При прерывании отправная точка — текущая поза.** Сначала прочитайте текущие координаты и масштаб, затем ведите к новой цели. Не начинайте второй переход из старого конечного состояния.
5. **Опора сообщения неподвижна.** Сначала выбирается хвостик как центр преобразований, затем одновременно применяются масштаб, изменение формы и поворот.
6. **Жест и переход — разные фазы.** Пока палец на экране, прогресс зависит от расстояния. После отпускания успешный жест продолжает общий переход во времени.
7. **Уменьшение движения не выключает функцию.** Состояние, кнопки, тост и возможность отмены остаются.

## Единицы и начало отсчёта

| Обозначение | Как читать |
|---|---|
| мс | Миллисекунды; 1 000 мс = 1 секунда |
| Логический размер / pt | Размер в раскладке. На Android используйте соответствующий размер в dp, на Web — CSS px с учётом вашей сетки; не копируйте физические пиксели видео |
| Масштаб 1 / 100% | Обычный размер элемента |
| Деформация 1 | Обычное соотношение сторон; отдельно от общего масштаба |
| Угол в градусах | В координатах экрана положительный поворот по часовой стрелке |
| Задержка | Время от события до начала конкретного движения, не общая длительность |
| Длительность | Время движения после задержки |
| Непрозрачность 1 / 100% | Полностью непрозрачная заливка |

В страницах 05/08 отсчёт начинается от обновления **видимой** коллекции после закрытия форм. У подсказки — от готовности впервые появиться. У сердца — от первого сохранения. У протяжки до отпускания вообще нет временной шкалы.

## Как перенести движение на другую платформу

Для обычного перемещения можно использовать кривую с плавными стартом и остановкой. Для упругого роста используйте пружину вашего движка и сверяйте: старт, первый перелёт размера, один отклик, время успокоения. Не надо переводить любой эффект в длинный список точек Безье.

В SwiftUI есть два похожих параметра:

- `response` — настройка скорости пружины, здесь указана в мс; это **не точная длительность перехода**.
- `dampingRatio` / `dampingFraction` — сила затухания. Чем ближе к 1, тем спокойнее остановка; меньшие значения дают более заметный отклик. Это не количество отскоков и не проценты прозрачности.

Для keyframe-пружин также задана длина участка таймлайна. Она ограничивает этот участок; не путайте её с `response`. Передавать числовые параметры между разными движками один к одному не обязательно: сначала совпадение видимого поведения, затем тонкая настройка.

| Эффект / свойство | Участок таймлайна | response | Затухание |
|---|---:|---:|---:|
| Подсказка: размер | 540 мс | 380 мс | 0,66 |
| Подсказка: успокоение формы | 680 мс | 320 мс | 0,72 |
| Подсказка: возврат поворота | 600 мс | 360 мс | 0,70 |
| Новая карточка: размер | 460 мс | 340 мс | 0,66 |
| Новая карточка: форма | 480 мс | 280 мс | 0,74 |
| Рекомендация: размер | 600 мс | 320 мс | 0,70 |
| Рекомендация: форма | 600 мс | 280 мс | 0,74 |
| Перелёт в сетку | До завершения пружины | 560 мс | 0,86 |
| Move In | До завершения пружины | 420 мс | 1,00 |
| Отмена протяжки | До завершения пружины | 380 мс | 0,86 |
| Лейбл суммы | До завершения пружины | 340 мс | 0,86 |

Для сравнения независимой реализации есть [JSON](motion-reference.json): имена свойств, единицы, задержки и пробы значений каждые 16,667 мс из настоящих таймлайнов. `progress` означает долю пути от измеренной исходной позиции к измеренной целевой. Это справочные данные, а не требование воспроизводить движение дискретными ступеньками по 60 кадрам.

## Состояния коллекции

```text
спокойный список
  → получили новый состав
  → запомнили текущие позиции / видимость
  → назначили новые слоты по id
  → двигаем соседей с задержкой
  → доиграли и убрали временные представления
```

При удалении данные уже не содержат карточку, но её визуальный снимок временно остаётся, чтобы схлопнуться. Он не нажимается и исключён из доступности. Нельзя сразу удалить его из отображаемого массива: иначе получится исчезновение одним кадром.

Отмена во время схлопывания возвращает этот же объект из текущего масштаба. Отмена после завершения добавляет объект на прежнее место с обычным появлением. Высота последней строки удерживается до окончания движения. Внутреннее завершение пакета через 1 350 мс — запас для очистки состояния, **не обязательная видимая пауза и не блокировка UI**.

## Границы прототипа и задачи интеграции

- Хранилище в памяти. Нужны реальные загрузка, сохранение, ошибки сети и согласование с сервером; этих контрактов прототип не задаёт.
- Детали операции используют собственное локальное состояние сохранения. Для продукта его нужно объединить с общим источником избранного.
- Даты, частота операций, суммы и поставщики демонстрационные. Текст «Скоро оплата» не означает, что реализован планировщик или автосписание.
- Тактильный отклик в коде есть у жеста и действий, но запись и симулятор его не передают. На реальном устройстве сверяются лёгкие шаги раскрытия, готовность и подтверждение; системные настройки тактильности имеют приоритет.
- Возврат из сетки сейчас не повторяет полёт карточек в обратную сторону.
- Покачивание — сигнал редактирования. Перетаскивание для ручной сортировки не реализовано интерфейсом.
- Эксперимент с папкой изолирован; продуктовый порог показа для 7 / 8+ карточек не утверждён.
- Покадровые позиции переживают повторное изменение, но скорость не переносится как отдельное физическое состояние. Это не обещание строгой непрерывности скорости при любом количестве быстрых действий.

Эти пункты не предлагается достраивать по догадке. Они явно отделяют существующее поведение прототипа от решений продуктовой разработки.
