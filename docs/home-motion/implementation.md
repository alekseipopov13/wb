## Единицы и кривые

Все размеры — CSS px при масштабе интерфейса 1×. На нативной платформе используйте логические pt/dp и фактическую геометрию раскладки. Не переносите пиксели записи 2×.

| Кривая | Где используется | Характер |
|---|---|---|
| cubic-bezier(0.22, 1, 0.36, 1) | Число и ширина суммы 400 мс; карточки 400 мс | Быстрое начало, мягкое завершение |
| cubic-bezier(0.4, 0, 0.2, 1) | Ширина группы карточек 500 мс | Плавное перераспределение места |

Это временные кривые, не пружины. Для параметрической Bézier сначала решите X(u)=t/duration, затем используйте Y(u). Подстановка t прямо в Y(u) даст другую скорость.

## Число, кегль и центр

Конечный кегль выбирается по [масштабированию](amount-scaling.md). Для перехода используются текущие число, кегль и ширина; целевые значения рассчитываются один раз. Все величины получают один временной прогресс от 0 до 1 за 400 мс с cubic-bezier(0.22, 1, 0.36, 1). Отведённая ширина плавно переходит между состояниями. Кегль меняется только если начальный и конечный размеры отличаются. Если сумма помещается базовым размером, его сохраняем; число символов не является условием уменьшения.

Пересчёт очень разных сумм проходит порядки величины. Переход к следующему разряду допускается, когда кегль уже позволяет разместить его в отведённой ширине. Это не линейное распределение денежной разницы по времени. Когда нужен другой кегль, он меняется одновременно с числом в обоих направлениях. Если оба значения помещаются одним кеглем, размер не анимируется. Не вставлять предварительное уменьшение или последующее увеличение.

Центр строки «число + ₽» постоянен. Глазик не входит в центрируемую группу: он движется справа вслед за резервируемой шириной, без масштабирования. В покое зазор до области кнопки — 8 единиц макета; во время движения резерв может делать его больше. Цифры имеют естественные табличные ширины текущего шрифта, без горизонтального сжатия и заранее заданного лимита разрядов.

Новый тап перенаправляет весь переход из текущего состояния за 400 мс. При уменьшении движения сразу показать конечное число и геометрию. Имена компонентов и архитектуру выбирает команда платформы. [Поведение и примеры](animations/01-balance.md).

## Единый прогресс без рывков

Это модель поведения, без привязки к компонентам или технологии платформы. Перед переходом фиксируются текущее видимое состояние и цель. Конечный кегль выбирается по фактической ширине один раз; шаг 10% не используется для видимого движения. При неизменных условиях раскладки не выполнять новый подбор кегля для каждого промежуточного числа.

Для одного общего прогресса `p` после временной кривой:

- `кегль(p) = начальныйКегль + (конечныйКегль − начальныйКегль) × p`;
- `резерв(p) = начальнаяШирина + (конечнаяШирина − начальнаяШирина) × p`;
- левый край области глазика находится в `центрСуммы + видимыйРезерв(p) / 2 + зазор`;
- `видимыйРезерв` ограничен доступной шириной текста; переполнение на минимальном кегле скрывается fade внутри этой области;
- число выбирается на согласованном с местом пути через порядки величины; на `p = 1` оно точно равно цели.

Центр относится к строке «число + ₽» и не включает глазик. Глазик следует за резервом, а не за измеренной шириной каждого промежуточного значения. Зазор в покое — 8 единиц макета; временный запас места допустим. Если ширины совпадают, глазик неподвижен. Если кегли совпадают, кегль неподвижен. Все непрерывные величины сохраняют дробную точность; целым становится только отображаемое число рублей.

₽ получает тот же текущий кегль, что цифры; отдельная иконка — тот же относительный масштаб без собственного таймера. Выравнивание по базовой линии сохраняется. Глазик и его область нажатия не масштабируются. Фактическая строка центрируется в резерве; её пропорции не искажаются ради заполнения ширины.

При новом нажатии началом становятся текущие видимые число, размер, резерв и положение глазика. Новая цель достигается за 400 мс, без возврата к исходным или прежним конечным значениям. На последнем кадре не запускать повторную подгонку размера или размещения. [Покадровая приёмка](animations/01-balance.md#покадровая-приёмка).

## Карточки

Хранить две группы постоянно, с устойчивыми идентификаторами. Общий слот имеет анимируемую ширину; группы наложены в нём с одинаковым X=0. Скрытие — Y=115 px под overflow-маску, показ — Y=0. Сосед «Открыть ещё» следует за шириной слота. ВТБ и разделитель составляют один движущийся объект.
