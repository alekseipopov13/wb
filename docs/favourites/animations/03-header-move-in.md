# 03 · Открытие по заголовку: Move In

[← Все взаимодействия](../README.md) · [Логика раздела](../behaviour.md) · [Справочник значений](../motion-reference.json)

Статус: реализовано в прототипе. Единицы: мс и логические размеры интерфейса. Отсчёт времени начинается от события, описанного ниже.

## Зачем

Открыть полный раздел понятным переходом, когда в текущем кадре нет сохранённых карточек, которые могли бы туда перелететь.

## Как запускается

Тап по «Избранное» в начале ленты, где видны только рекомендации/системные действия; также используется при пустом избранном. Видимость определяется фактическим пересечением карточки с экраном.

Отдельный пример: `-demoOpen favourites-animations/header-move-in`.

## Пример и последовательность

![Открытие по заголовку: Move In — запись интерфейса](../media/03-header-move-in.gif)

[Видео с исходным темпом движения](../media/03-header-move-in.mp4) · [Раскадровка записи](../media/03-header-move-in-frames.jpg)

| Этап | Что происходит |
|---|---|
| Тап | Создаётся конечный экран сетки, измеряется его размер |
| Открытие | Сетка заезжает справа от одной ширины экрана до нулевого смещения |
| Одновременно | ПиП немного уходит влево: до 22% ширины экрана |
| Завершение | Новый экран принимает нажатия; исходный не перехватывает фокус |
| Назад | Переход возвращается в исходное состояние за 240 мс |

## Параметры и их смысл

| Параметр | Значение | Зачем |
|---|---|---|
| Начальная позиция сетки | На одну ширину экрана правее | Направление перехода читается без абсолютных координат |
| Смещение исходного экрана | −22% ширины | Даёт глубину, не уносит оба экрана одинаково |
| Пружина открытия | Скорость 420 мс, затухание 1 | Мягкая остановка без заметного перелёта |
| Прозрачность обычного перехода | 100% | Основное движение — слайд |
| Возврат | 240 мс, плавный разгон/торможение | Быстро возвращает в ленту |

420 мс — параметр пружины, а не таймер окончания. Взаимодействие включается по фактическому завершению анимации.

## Повторное действие и прерывание

Повторный тап во время открытия игнорируется. Если пользователь сначала прокрутил к видимым избранным, следующий тап выбирает [перелёт карточек](04-header-flight.md). Эти два поведения сохранены намеренно для обсуждения, они пока не унифицированы.

## Уменьшение движения и доступность

Вместо большого перемещения экран проявляется за 150 мс. Возврат тоже занимает 150 мс. Конечная сетка и доступные действия совпадают с обычным режимом.

## Как проверить

- [ ] Из начала ленты карточки не прилетают из выдуманного места.
- [ ] ПиП и сетка движутся согласованно, без паузы между экранами.
- [ ] После возврата можно повторить переход.
- [ ] Пустое состояние открывается без карточек-призраков.
