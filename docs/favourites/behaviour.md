# Логика избранного

[← Обзор](README.md) · [Анимации](README.md#все-взаимодействия) · [Реализация](implementation.md)

## Лента и полный раздел — разные списки

Лента на ПиП помогает быстро повторить нужное действие. В неё входят системные подсказки, частые операции и максимум две отобранные карточки избранного. В полном разделе находятся **все явно сохранённые операции**, без автоматического превращения рекомендаций в избранное.

Один и тот же `id` обозначает одну операцию. Добавление уже сохранённого `id` не создаёт дубликат. Порядок сетки и порядок рекомендаций могут различаться: сетка получает новое избранное первым, лента сортирует подходящие операции по частоте.

## Как собирается лента

Всего допускается **до шести карточек операций**. Кнопка истории добавляется после них и в этот лимит не входит.

1. При подключённом Open Banking первой идёт карточка ВТБ.
2. Если истории ещё нет, далее идёт «Пополнить кошелёк».
3. Затем — мобильная связь. При пустой истории название обезличено: «Пополнить свой телефон».
4. Из оставшихся мест до двух резервируются под подходящие сохранённые операции.
5. Остальные места занимают частые операции, которых ещё нет среди избранных и фиксированных карточек.
6. В конце стоят отобранные избранные, затем «Добавить из истории».

| Данные | Ожидаемая лента |
|---|---|
| Истории нет, Open Banking выключен | Кошелёк → свой телефон → история |
| Истории нет, Open Banking включён | ВТБ → кошелёк → свой телефон → история |
| История есть | Кошелёк убирается; появляются частые операции |
| Есть частые и избранные | До шести операций, включая до двух отобранных избранных; затем история |

Частота — сначала количество использований, затем давность последнего использования; при равенстве сохраняется исходный порядок. Повторы одного `id` объединяются. Фиксированные действия не дублируются. Это алгоритм демонстрационной модели, а не описание готового серверного ранжирования.

## Открытие и оплата

Тап по заголовку открывает полный раздел. Если видимые избранные есть, используется [перелёт](animations/04-header-flight.md); иначе — [Move In](animations/03-header-move-in.md). В конце ленты можно открыть раздел [протяжкой](animations/02-deck-pull.md).

Обычный тап по сохранённой карточке открывает транзакционный шаг с реквизитами и сохранённой суммой. Если сумма не задана, её вводят перед оплатой. Для ЖКУ сначала запрашиваются переменные данные текущего месяца: например, новые показания счётчика. Старые показания не выдаются за новые.

Транзакционный экран использует общую основу ПиП «Между счетами», результат — первую версию общего `OutcomeScreen`. V2 находится в архиве. Эти экраны не дублируются внутри избранного.

## Создание из истории

История показывает недавние операции. Уже сохранённые отмечены и недоступны для повторного добавления. После выбора открывается редактор. Нажатие «Добавить» закрывает редактор и историю; только после их полного закрытия начинается [вставка в сетку](animations/05-grid-insertion.md). Лента обновляет подборку без анимации вставки и без автопрокрутки.

## Редактор избранного

| Состояние | Поведение |
|---|---|
| Создание | Одна кнопка «Добавить»; фокус сначала на названии |
| Изменение | Две кнопки: «Сохранить» и «Убрать» |
| Название | После удаления пробелов по краям не может быть пустым; максимум 40 символов |
| «Без суммы» | Поле суммы выключено, значение шаблона означает отсутствие суммы; реквизиты сохранены |
| С суммой | Допускается значение больше нуля и до 1 000 000 ₽ включительно, до двух знаков после разделителя |
| Быстрые суммы | Сумма исходной операции, затем 500 и 1 000 ₽ без дублей |
| Ручной ввод | Меняет сумму шаблона, но не переписывает сумму исходной операции для быстрого чипса |

В форме из истории предлагается исходная сумма операции. Если шаблон уже сохранён «Без суммы», редактирование сохраняет это состояние; сумма операции остаётся доступна отдельным чипсом.

Поле — общий `InputText` / `InputPrice`. **Один и тот же лейбл** «Сумма» перемещается и меняет размер: 17 → 13 при заполнении, обратно при очистке/выключении. Он поднимается на 10 единиц от центра; текст значения опускается на 8,5. Пружина: скорость `response = 340 мс`, затухание `0,86`; это параметр скорости, не обещанная длительность. При Reduce Motion переход мгновенный. Отдельной демонстрационной страницы анимации инпута нет.

Большой логотип имеет размер 80 × 80, радиус **20**, поворот −5°. Поле названия перекрывает его и имеет внешнюю обводку в цвет фона толщиной 4: она визуально отделяет поле от логотипа. Это не обводка ошибки или фокуса. Маленькие аватары карточек остаются круглыми.

## Редактирование и удаление

Карандаш включает [покачивание и крестики](animations/07-wiggle.md). В этом режиме тап по карточке открывает редактор, крестик — [удаление](animations/08-removal.md). После удаления сетка возвращается в обычный режим. Тост хранит только последнее отменяемое удаление и живёт пять секунд от изменения данных. Отмена восстанавливает прежнее место относительно соседей; не включает редактирование.

При удалении последней карточки появляется пустое состояние: иконка архива и «Здесь будут ваши избранные». Кнопка истории остаётся доступна. Сами рекомендации на ПиП не удаляются только потому, что пользователь убрал их из избранного: после пересчёта они могут остаться как частая операция.

## Детали операции

Первый тап «В избранное» немедленно меняет локальное состояние на сохранённое и запускает [Pow Pop](animations/09-heart-pop.md). Текст становится «В избранном». Второй тап открывает редактор с «Сохранить» и «Убрать»; он не удаляет операцию автоматически.

**Граница демонстрации:** `OperationDetailsScreen` хранит своё состояние отдельно от `PaymentsFavouritesStore`. Между этими двумя независимыми примерами нет готовой синхронизации и сохранения после перезапуска. В реальном приложении они должны работать с единым хранилищем.

## Папка «Все избранные» — эксперимент

Только «Новый вариант» добавляет после операций и перед историей папку. **N — общее количество сохранённых**, а не число скрытых. В группе — первые четыре настоящих логотипа из полного списка. За папкой могут выглядывать до двух скрытых карточек с непрозрачной заливкой и обводкой.

В текущем эксперименте папка показывается при любом непустом избранном, даже если скрытых нет. Это не принятое общее правило для 7 / 8+ карточек. В основной сценарий его автоматически не переносим.
